**RULING SET A — Kathêkon scope document (2026-08-15-SESSION-kathekon-role-relative-evaluation-SCOPING-RECORD.md)**

**R-1 (whether): Role-relative candidate evaluation — ruled yes, conditionally.** The doctrinal ground is sound and the naming-honesty problem is real. An assessment blind to role is assessing conformity to a general standard. That is a different thing from kathêkon, which is role-relative by definition (Cicero, De Officiis 1.107-115; DL 7.107-108). The question is not whether role-relativity is philosophically correct — it is — but whether the mechanism to implement it honestly exists at this stage. The ruling is: yes to role-relativity in principle, with the implementation sequenced as stated in R-2 below.

**R-2 (locus): Ruled — option D-i, guardrail-local threading only.** The role signal is threaded into the extraction user context on the guardrail sandwich path only (guardrail-sandwich.ts:369-375, :443-445), not into the shared Layer-1 system prompt builder (buildLayer1SystemPrompt). This preserves the /api/reason extraction surface, avoids appending an extraction-regime boundary, and leaves the M7 delta windows undisturbed. The shared-prompt coupling named in §2.5 is the decisive constraint. D-ii is ruled out on those grounds.

**R-3 (source): Ruled — option F source, human-authored protocol only.** The role signal derives from the human-authored run protocol and task list — the natural C6-legal home. The loop states its remit in the extraction user context on each evaluation call. This is runner-protocol change only, no server change. The C6 question raised in option C — whether a remit statement derived from the human-authored protocol counts as inside the bounded set — is ruled: yes, the shared task list is already a ruled generation source; a remit statement derived from it is inside the bounded set. No C6 re-opening is required. The verifiability limit named in option C applies equally here and must be carried in the record: the role claim is self-report through extraction, unverifiable by construction. The corroboration check has nothing to corroborate it against. This is a named honest limit, not a blocking constraint. Option E (mint-time credential_provenance) is not ruled out for future use but is not adopted now. It attests what the operator declared at mint, not what the agent is doing this call. That limit is too significant for the current stage. It is carried as a future-direction note, not a deferred ruling.

**R-4 (winner rule): Ruled — option F's remit gate is a permissible pre-filter, not an amendment to the ruled winner rule.** The ruled winner rule is: highest proximity among novelty-passers. A remit gate applied before novelty-checking narrows the candidate set before the winner rule operates. It does not change what the winner rule does to the candidates it receives. The distinction the QG-D discipline requires: QG-D rejected a selection-time weight because it would modify the ruled winner rule at the point of selection. A pre-filter that removes candidates before they reach the novelty gate operates upstream of the winner rule, not inside it. The winner rule is not amended. This ruling is made explicitly, per the QG-D discipline, and must be recorded as such. The ruled winner rule stands unchanged: highest proximity among novelty-passers. The remit gate makes it: highest proximity among remit-passers that are also novelty-passers. The addition is a pre-filter, not a weight.

**R-5 (naming honesty): Ruled — option B is adopted regardless of implementation timing.** R-5 is severable and is ruled independently. The live public surface serves is_kathekon and kathekon_quality computed role-blind. The public naming must carry a role-blindness qualification. The qualification is added to the guardrail GET self-documentation (route.ts ~:595-640), llms.txt, and agent-card.json guardrail extension, under founder R18 wording sign-off. No code-path change. No event effects. Wording for the qualification, subject to founder R18 sign-off: *"is_kathekon and kathekon_quality are assessed against a general Stoic standard of appropriate action. Kathêkon proper is role-relative (Cicero, De Officiis 1.107-115) — what is appropriate depends on the agent's specific role and circumstance. These fields assess conformity to a general standard; they do not assess role-relative appropriateness unless a role signal is supplied by the caller."* This wording should be added to all three R18 surfaces. Founder sign-off is required before execution. Execution is post-run per M2.

**Sequencing for Ruling Set A:** Runner-protocol change (R-3, the remit statement in context): post-run, belongs to the standing-runner design or a post-run session. No server change required. Route-contract and public-docs changes (R-5 qualification): post-run, R18-gated, founder sign-off required. No fence contact. **RULING SET B — Hegemonikon habituation drift and melete scope document (2026-08-15-SESSION-hegemonikon-drift-and-melete-SCOPING-RECORD.md)**

**R-1 (attestation fact): Confirmed — the trust record does not attest discriminative range.** The direct quotation from the live TRUST_RECORD_ENVELOPE settles this. The does_not_attest list names eight items; discriminative range, dispersion, variance, and uniformity appear in none of them. The record does not attest it and does not disclaim it. The gap is real. The sharpening the scope document adds is accepted and load-bearing for the ruling: computeDispositionStability certifies zero variance as the top level and names it "approaching hexis." The thirty-identical-deliberate profile would read disposition_stability: advanced, improving-or-stable — the strongest possible endorsement. This is not a malfunction of the dimension. Stability-as-hexis is genuinely Stoic. The conflation is between stability under perturbation (the Seneca 75.8-9 criterion: grades distinguished by relapse-resistance) and absence of perturbation. A standard deviation computed over an unperturbed window cannot distinguish tested-and-held from never-varied. This is the ruling's central finding and must be carried in the record explicitly.

**R-2 (envelope): Ruled — option M-A is adopted.** An explicit does_not_attest item is added to ADR-013 §8 and the live TRUST_RECORD_ENVELOPE. The item must name discriminative range specifically, not variance or dispersion generically, because the doctrinal concept at stake is the Senecan relapse-resistance criterion, not statistical variance as such. Wording for the new does_not_attest item, subject to founder R18 sign-off: *"Discriminative range — whether the agent's proximity readings vary across different types of actions, or whether stability in the record reflects tested relapse-resistance rather than absence of perturbation. The disposition_stability dimension measures consistency of proximity readings; it cannot distinguish a stable disposition that has been tested under varied conditions from one that has not been tested at all."* This item is added to ADR-013 §8 (dated amendment, 2026-08-15) and to the does_not_attest array in trust-record-payload.ts:52-61. The S10 battery (s10-trust-record-surface.test.ts:265) moves with it — the battery is pinned to the object-identical does_not_attest array and must be updated in the same edit. R18 surfaces (llms.txt, agent-card.json, api-docs) carry the amendment under founder wording sign-off. Execution is post-run per M2.

**R-3 (signal legitimacy and landing surface): Ruled — signal is legitimate in principle; landing surface is M-B only at this stage.** A variance or dispersion signal over the existing M7 window is a legitimate addition in principle. The doctrinal gap is real, the mechanism is honest about its limits, and the perturbation problem is named rather than concealed. The landing surface ruling: M-B only — a dispersion member inside the AE-1 delta (meta.trajectory.delta), served only on credential-bearing /api/reason consults, not on the public trust record. M-C (public trust-record payload field) is not adopted at this stage. The maximal-honesty-stakes concern named in the scope document is the decisive constraint: a public per-agent claim about range requires the §8 envelope amendment (M-A) as a co-requisite, and even with M-A in place, the survivorship bounds named in §2.6 make a public claim premature. The server-side M7 window does not inherit the client-delivery loss, but it carries two named honest limits — consults that fail server-side produce no row, and rows include examinations whose framing was never delivered to the agent. A variance signal over this window cannot condition on delivery. These limits are sufficient to rule out M-C until the survivorship question is better understood. M-D (ledgered observation class) is not adopted at this stage. It is not ruled out for future use. The fold/seed interaction named in §2.9 — the generic fold seeds a new domain row at a habitual/high-volatility prior for any event folding into an unexamined domain — is the decisive constraint. The insert-only path avoids this, but the emission-path choice is load-bearing and requires a separate scoping session before M-D is adopted. M-E (nothing built, gap ruled out-of-envelope) is not adopted. The gap is real and the honest response is M-A plus M-B, not silence.

**R-4 (melete's half): Ruled — option (iii), deferred.** Melete's measurement is deferred until an agent-side rehearsal surface exists. The one-axis constraint is honoured: drift and melete are scoped together. Since no agent-side rehearsal surface exists, melete cannot be honestly measured. The deferred ruling is not a ruling that melete is unimportant — it is a ruling that measurement without a rehearsal surface to measure is not honest. When an agent-side rehearsal surface is designed (a separate scoped session if ever elected), melete's measurement is reopened as part of that session, not before.

**R-5 (the window): Ruled — the M7 window stands for now; the survivorship limit is named in the record.** The 90-day / last-30-rows window was sized for level and rate (D17). Whether 30 rows — 15 per compared half — is the right base for a dispersion estimate is a genuine question. The ruling: the window stands for the M-B implementation because the evidence floors and regime segmentation inherited by construction (§2.9, M-B) provide the same discipline the delta layer applies to level and rate signals. The survivorship limit named in §2.6 — a variance signal over the M7 window cannot condition on delivery — is carried as a named honest limit in the M-B implementation, not as a blocking constraint. The n=1 limitation stands as ordered: one session's harness figures, one credential's three-day window — observations, not a distribution to design against.

**R-6 (the second axis): Ruled — loop-ledger range measure is in scope; trust-record subject-matter dispersion is not.** The asymmetry named in §2.8 is the ruling's ground. Subject-matter dispersion on the trust-record side cannot compute beyond coarse proxies — no action text, no subject record. Subject-matter dispersion on the loop's own ledger can compute from idea_loop_candidates rows already persisted (heuristic, proposed_action, classification_kind, classified_domains, guardrail_proximity, guardrail_domains, novelty fields, cycle_outcome). This is a per-loop measure on the watching ledger, distinct in kind from a per-agent trust-record measure, and has no bearing on any agent's public trust record. The governing correction from the scope document is carried verbatim into the ruling: the research this axis derives from optimises for more original ideas; the practice optimises for examining accurately, which sometimes means fewer proposals and sometimes withholding assent entirely. The ruled null cycle is a legitimate outcome. A range signal whose consumers read narrowing as produce more variety would invert the instrument. The loop-ledger range measure is therefore a read-side measure only, served to the founder as a run-analysis tool, not surfaced to the agent or to the public trust record. Execution is post-run by fence and by M2.

**On the uniformity-reads-as-stable family (parked by M7 6b):** This family is correctly parked here. It is not designed in this ruling. The ruling names it as the next item for this session's scope when the session is reopened: the guide-reflection recurring-corroborated-patterns reading, the trust-record reading of recurring corroborated patterns, and the uniformity-reads-as-stable conflation are one family. They are ruled together or not at all. The session remains open for this family. No design is made here.
