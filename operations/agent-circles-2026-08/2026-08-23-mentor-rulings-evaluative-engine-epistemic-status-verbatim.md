**EE-A2 — The provenance of deterministic computation over inference**

**Ruling:** Option (a) — inference, inheriting the weakest provenance of the field's inputs, with the computation's determinism expressed on a different axis.

The reasoning: the four-value provenance vocabulary answers how a proposition arrived. A Layer-2 computed field arrives by deterministic computation over Layer-1 inference. The computation does not change the proposition's epistemic origin — it transforms an inference into a derived inference. The weakest-provenance-inheritance principle is the honest expression of this: if the input is inference, the output is inference, regardless of how reliably the transformation was performed. The signature attests the transformation's reproducibility, not the input's truth — which is precisely the separate axis the document names.

Option (b) — a fifth provenance value — is declined. A "computation" value would make a different epistemic claim: that computation is a distinct epistemic origin, parallel to observation, inference, assumption, and unknown. It is not. Computation is a transformation method, not an epistemic origin. The document's own lean is correct; the ruling confirms it.

Option (c) — a compound entry with a named derivation disclosure — is not elected as a vocabulary amendment, but the derivation disclosure itself is warranted. The honest form is: { provenance: inference } with a named derivation note (not a new vocabulary value) stating that the inference is deterministically derived from Layer-1 extraction. This note rides the documentation map (Shape 1) or, if Shape 2/3 is elected, as an additive field alongside the provenance entry. It does not change the provenance value; it contextualises it.

**EE-A3 — The credence axis for engine outputs**

**Ruling on (i):** The existing three-grain machinery already constitutes the engine's credence expression, in per-mechanism vocabularies. Whether a fourth, uniform credence value is worth adding is EE-B2's question. EE-A3's structural ruling is: the engine can honestly carry a credence value only if it is deterministically derived from the existing machinery — the ambiguity_notes, stage_scores, corroboration findings, evidence floors. Any new LLM judgement of likelihood would be a new inference layer, which is structural revision outside this scope. That constraint is confirmed.

**Ruling on (ii):** Deterministic derivation from the existing machinery is the only honest assignment path. Confirmed.

**Ruling on (iii):** The corroboration vocabulary (corroborated / uncorroborated / contradicted) and the ruled credence vocabulary (established / probably-true / unknown / probably-false) are derivation inputs, not a mapping. The document's three options are: mapping, derivation input, or deliberate coexistence. A mapping would claim that corroborated means probably-true — which is not always true (a corroborated inference can still be probably-false if the corroborating evidence is itself weak). A derivation input is the honest relationship: corroboration findings are one input to a credence derivation, not a synonym for a credence value. The corroboration vocabulary's routing role is untouched by this ruling.

The derivation-circularity worry named in §7.2 is real and is not dismissed. A credence derived from ambiguity_notes + stage_scores + corroboration findings may restate those inputs in a second vocabulary without adding information. EE-B2 should hold this worry explicitly when pricing Shape 3.

**EE-C1 — Quiet site #1's label**

**Ruling on (i) — the wording:** The string should carry its derivation explicitly. The directed wording is accepted with one revision:

*Current:* "No kathekon factors detected; action is contrary to appropriate action."

*Ruled wording:* "No kathekon factors were extracted from the submitted text; on that basis, the engine reads the action as contrary to appropriate action."

The document's proposed direction read "on that absence" — the ruled wording substitutes "on that basis" because "absence" can read as a claim about the world (no factors exist) rather than a claim about the extraction (no factors were found in the text). "On that basis" is the honest expression: the engine's reading is grounded in what the extraction produced, not in a claim about what the action contains. The classification and every downstream consequence are unchanged.

**Ruling on (ii) — where it rides:** The wording change is made in place — the justification string is reworded at layer2-mechanisms.ts:1271-1274. An additive disclosure note alongside it is not elected.

An additive note alongside it would create two disclosure channels for the same claim, which is the drift risk EE-B2 names. The in-place rewording is a single change to a single string; it is cleaner and less drift-prone than an additive note.

This is a wire change on both measured surfaces (the signed assessment and the live guardrail verdict). It is PR19-reviewed code-critical work. It is not licensed by this ruling — the ruling fixes the wording; the build scoping licenses the implementation.
