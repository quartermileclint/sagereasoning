**Q1 — Agenda ordering**

**Ruling:** Gate 3 sequences the five L-2 dimensions by evidentiary weight — (c) first (as already ruled at Ruling Set D), then (d), then (a), (b), and (e) on the existing architectural material alone.

The reasoning is not merely that the §6 data happens to evidence (c) and (d) more than the others. It is that dimension (c) is load-bearing by ruling — the honesty question about interior-access presumptions is the question that determines whether any rendering is honest at all, regardless of what it contains. The sequencing by evidentiary weight is therefore not a concession to what the data happened to produce; it is the correct order because (c) is the condition of possibility for the others. A rendering that presumes interior access it cannot verify is dishonest regardless of how well it handles reader identity, relay structure, affordance naming, or relational context. Gate 3 should address (c) first because it must, and the §6 data now makes (c) concrete rather than hypothetical — which is the additional reason the sequencing is right, not the primary one.

For (a), (b), and (e): Gate 3 addresses them on the existing architectural material. The run supplies no fresh data on the relay case, the crisis-path relay pattern, or the relational dyad. Gate 3 should not manufacture evidence it does not have. The honest posture for (a), (b), and (e) is to reason from the architectural material already established — the relay precedent, the R20d boundary, the runner-remit self-declaration honest-limit class — and to name explicitly where the design is constrained by absence of evidence rather than filling the gap with inference.

---

**Q2 — The disclosure-generalisation question**

**Ruling:** Yes. Gate 3's dimension-(c) work starts from the specific question of whether L-5's "disclose the posture, don't presume the access" discipline generalises from the reflect surface to the consult-rendering surface.

The relay-time drift note strengthens this ruling's premise: L-5 has now executed. The discipline is not merely ruled — it is live on the reflect surface. The question for Gate 3 is therefore not hypothetical: it is whether a discipline already operating on one surface applies to an adjacent surface, given two now-measured instances (delivery-timeout gap at 14% of orientation events; cross-endpoint divergence currently visible to no one but the founder) that make the gap concrete.

Gate 3 should address this question in the following form: what would the consult-rendering surface say about a result whose delivery classification is examined rather than observed, and what would it say about a result where the cross-endpoint check shows divergence? The answer to both is a design question for Gate 3, not a ruling question for this document. But the starting point — L-5's discipline as the generalisation candidate — is confirmed.

---

**Q3 — The cross-endpoint finding's audience**

**Ruling:** These are genuinely distinct questions, and the ruling says so explicitly.

Ruling Set D's B/R-6 scoped the B7 cross-endpoint check as read-side, founder-facing, for the loop's own reporting purposes — a range measure inside the loop's own report. That question is: what does the founder see about the loop's internal consistency?

O-C's design question is different: what does the practitioner whose action produced the divergence see, if anything, from the consult surface itself? The actor is different (founder versus practitioner), the surface is different (loop report versus consult rendering), and the moment is different (post-run analysis versus real-time consult response).

Gate 3 should treat "should any form of this comparison's result ever reach the practitioner whose action produced it" as in scope for the per-consumer rendering design — it is the honesty question dimension (c) asks, applied to a specific, now-verified instance of divergence. This does not reopen B/R-6 or move any of R8's gates. B/R-6 governs what the founder sees in the loop report; Gate 3 governs what the practitioner sees in the consult rendering. Both can be answered without conflict.

One constraint Gate 3 inherits from this ruling: if the design concludes that some form of the cross-endpoint comparison should reach the practitioner, it must answer the honest-limit question — the comparison classifies the caller at the transport level, not the downstream practitioner, and the flag-off asymmetry is historical. Any rendering of divergence must not presume it can characterise the practitioner's interior state from a transport-level signal.

---

**Q4 — The nine-candidate classification task's timing**

**Ruling:** The nine-candidate classification task is not re-sequenced. It remains R8's gating task. Gate 3 proceeds without it.

The reasoning: dimension (d) is partially evidenced by the §6 data — one sharp instance (the attribution gap in the guardrail calibration limit) is enough to make the design question concrete. Gate 3 does not need the full nine-candidate classification to address dimension (d) honestly; it needs to design for the class of case the one verified instance represents, and to name explicitly that the design is based on one verified instance with eight unclassified cases. That naming is itself the honest posture dimension (c) requires.

Re-sequencing a mentor-set gate on R8 to serve Gate 3's convenience would be a false economy — it would delay R8's close to sharpen a design question that can be addressed honestly with the evidence already available. The scoping document is correct that it has no standing to move R8's gate, and this ruling confirms that standing.

What Gate 3 should do instead: design dimension (d) at the level of the class the one verified instance represents, name the eight unclassified cases as a known gap, and produce a design that degrades gracefully when the attribution is uncertain — rather than a design that presumes the classification is always recoverable.

---

**Q5 — Generalisability caveat, explicit or implicit**

**Ruling:** The caveat is sufficiently carried by this scoping document. Gate 3 need not restate it in full, but should carry a single sentence naming the single-loop-identity basis of the §6 data — not as a disclaimer, but as a design constraint.

The sentence should appear in Gate 3's design document wherever the §6 data is cited as evidence for a design choice, so that the design's evidential basis is visible at the point of use. The form: "The §6 data is a single credentialed loop identity's 20-cycle consult history — a verified instance, not a survey of agent practitioners in general." That sentence, placed at the point of citation, is sufficient. It does not need to appear in a separate section.
