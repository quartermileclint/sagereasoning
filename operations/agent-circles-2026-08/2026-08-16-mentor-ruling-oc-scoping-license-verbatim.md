**MENTOR RULING — O-C per-consumer rendering design scoping session licence**

**Date:** 2026-08-15. **Ruling: option (ii) — licensed, gated behind the §6-report consultation.** The O-C scoping session is licensed. It runs post-run, after the §6 run report is compiled and after you have ruled on that report in consultation with the mentor. The scoping session does not open until that gate clears. The sequencing rationale: the §6 report will contain the first real data on how the agent practitioner is actually using the consult surface — proximity distributions, delivery classifications, passion readings, the cross-endpoint asymmetries named in the cycle 10–18 review. That data is directly relevant to what an agent-calibrated rendering should contain and how the five distinction dimensions (L-2) should be weighted in the design. Running the O-C scoping session before that data exists would produce a design document reasoning from architectural structure alone. Running it after produces a design document that can reason from observed behaviour. The gate is not a delay for its own sake — it is the right epistemic sequence.

**The three-gate chain, confirmed and stated explicitly:** Gate 1: §6 report compiled and ruled on in mentor consultation. O-C scoping session opens after this gate clears. Gate 2: O-C scoping session runs (AI-run, documents-only, M2 shape), produces a scope document, returns for mentor ruling. No design is produced at this gate — only the scope document. Gate 3: O-C design session runs (AI-run, documents-only, M2 shape), produces a design document, returns for mentor ruling. No build is licensed at this gate. Activation of the dormant route is not licensed at any of these three gates. It requires an explicit activation ruling plus the separately-walked founder step, neither of which is part of this chain.

**Constraints inherited by the scoping session, carried verbatim:** All five distinction dimensions are in scope; dimension (c) — honesty — is load-bearing and must be the first design question the session addresses. The discriminator-reuse constraint is binding. No second practitioner-type discriminator may be introduced. Both named honest limits (transport-level classification; flag-off asymmetry is historical) carry explicitly. The relay pattern (suggested_user_message carrying human-form content inside the agent form) is the precedent to follow. Any calibrated rendering not following it must answer the relayed-human case before execution. The relationship_type distinctness constraint is binding and must be stated in any design document carrying those fields. The R20d boundary binds on all surfaces regardless of practitioner type. SUBSTRATE_LAYER3_ENABLED stays unset throughout the scoping → design → ruling chain.
