## 2. Origins of the Sage Practice — the methodology

### 2.1 The four disciplines → the four products

The practice is the operationalisation of the four classical Stoic disciplines as a closed cycle (`/adopted/sage-reflect-product-design.md:24-35`):

| Stage | Product | Discipline | Function | Status today |
|---|---|---|---|---|
| 1 | **Sage Calling** | Pre-action (purpose) | Find the fitting work | Live (`/api/calling`) |
| 2 | **SageReasoning** | In-action (impression/assent) | Examine the impression, reason it through | Live (`/api/reason`) |
| 3 | **Sage Assent** | At-action (impulse → act) | Credential or block the act; **hold the agent's persistent profile** | Live (accreditation + guardrail surfaces) |
| 4 | **Sage Reflect** | Post-action (continuous attention / prosoche) | Review what occurred, update the profile, decide if the purpose still fits | Live (`/api/practice/reflect`) |

> "The loop closes: Calling → Reasoning → Assent → Reflect → (RS-1) back to Reasoning, or (RS-2/RS-3) to Calling. **No stage is optional; no stage can be bypassed without breaking the philosophical integrity of the sequence.**" (`sage-reflect-product-design.md:35`)

Sage Reflect "operationalises the fourth Stoic discipline — continuous attention over time (Seneca, *Letters* 83.2: examination of the entire day; Marcus, *Meditations*; Epictetus, *Discourses* 3.10: review of impression, assent, and impulse in sequence)" (`sage-reflect-product-design.md:20`). Prosoche is therefore not a scored dimension — it is enforced *structurally*, by the session-close reflect discipline and its fabrication defences (FD-R1 null-result suspicion; FD-R3 mandatory pressure-assent sub-question — `sage-reflect-product-design.md:179-184`).

R19e makes the cycle's integrity a *marketing-honesty rule*: a configuration without Reflect "may support virtue-grounded reasoning within individual sessions, but not ongoing virtue development, progress tracking, or profile consolidation" (`manifest.md:218`).

### 2.2 The examine-impressions loop

The loop the next-session prompt names (score → redirect → reiterate → reflect) is assembled from these adopted parts:

1. **Score** — the 4-stage conceptual evaluation sequence (`scoring.json`, canonical at the conceptual level): Stage 1 prohairesis filter → Stage 2 kathekon evaluation → Stage 3 passion diagnosis → Stage 4 virtue quality (`canonical-framework.md:150-159`). Implementation-level: the canonical 9+1 mechanisms (`canonical-framework.md:54-71`): prohairesis_filter; passion root/sub-species/causal-stage/false-judgement; oikeiosis stage/obligation; value_indifferent; virtue_domain_engaged; and the **composite mechanism 10, katorthoma_proximity, which "aggregates upstream outputs and reads from the practitioner's longitudinal record for the Senecan grade overlay"** (`canonical-framework.md:71`).
2. **Redirect** — every evaluation carries the correction: mechanism 5's `dominant_false_judgement` + `correct_judgement` projects as `improvement_path` (`canonical-framework.md:107`); the guardrail surface projects it as `proceed / proceed_with_caution / pause_for_review / do_not_proceed`; the mentor surface projects it as `sage_perspective` ("what would right reason suggest differently").
3. **Reiterate (re-examine after the correction)** — designed in three places: (a) **`prior_feedback`** — "using prior evaluation findings as deliberation context for the next evaluation is a longitudinal-reasoning feature" (`canonical-framework.md:132`, Coverage note A; the R5 wrapper pattern names the same loop: "guard + score + **optional iterate**", `manifest.md:125`); (b) **deferral resolution** (AC-15) — the practitioner returns to a deferred question and "the original instance score is updated retrospectively" (`ADR-RAG-MENTOR-ALT3-01:144-149`); (c) **FD-R2 cross-session comparison** in Reflect (`sage-reflect-product-design.md:182`). The methodology *expects* the corrected reasoning to be examined again; a single-pass score-and-move-on is not the designed loop.
4. **Reflect** — the session-close Q1–Q6 sequence reviewing the whole causal chain (phantasia → synkatathesis → horme → praxis → kathekon), updating the profile, and routing the cycle (RS-1 continue / RS-2-3 back to Calling) (`sage-reflect-product-design.md:109-157`).

### 2.3 The component concepts, with their canonical commitments

- **Oikeiosis (R0):** the expanding circles, with Cicero's five deliberation questions for obligation (`canonical-framework.md:65-66`); operationalised for purposeless agents in Sage Calling Q3's three tests — independence, unmet, proportion (`purpose-discovery-product-design.md:74-78`).
- **Kathekon vs katorthoma:** kathekon quality (`strong/moderate/marginal/contrary`) is a composite read across mechanisms 7+9 (`canonical-framework.md:102`); katorthoma_proximity is the five **qualitative** levels `reflexive | habitual | deliberate | principled | sage_like` (R6c, `canonical-framework.md:298`); the unity thesis forbids independent virtue scoring (R6b) and sets per-domain aggregation to the **lowest** domain (KP-04, `sage-reflect-product-design.md:213`).
- **Passion diagnosis:** 4 roots (epithumia/hedone/phobos/lupe) × sub-species, each carrying a named **false judgement** with a correct judgement — "diagnostic, not punitive" (R6d); eupatheia is never classified from a single instance ("classification requires longitudinal evidence (CONFIDENCE_WEIGHTED)", `operationalised-rules.md:205`).
- **Withholding as kathekon (AC-14):** deliberately *not* scoring is a first-class rule output, with OPEN_DEFERRAL flags and a resolution surface (AC-15) — not a failure mode.
- **No external witness (AC-18):** the deferral-resolution surface produces no shareable artefact — "virtue requires no external witness" (`ADR-RAG-MENTOR-ALT3-01:165-170`). Note the deliberate asymmetry with Sage Assent: the *accreditation* is the public artefact (the trust layer exists to be shown); the *examination* is not.
- **Honest determinism:** the architecture self-describes as "deterministic engine for the rule-like components of Stoic reasoning, with honest soft-gating for the components that are not rule-like — not 'fully deterministic'" (`ADR-RAG-MENTOR-ALT3-01:189`).
- **Longitudinality is methodology, not nice-to-have:** "virtue is a longitudinal practice… The same practitioner's response to the same domain over weeks and months tells a different story than any single instance" (`progression-delta.md:24-26`); "The progression delta is the architectural commitment that virtue is longitudinal. The engine's per-instance evaluation is **necessary but not sufficient**" (`progression-delta.md:360`). Rule 10's named inputs include "`practitioner_profile` (longitudinal — for Senecan grade overlay and directional modifier)" (`operationalised-rules.md:589`).

## 3. The private Stoic mentor — how the methodology was meant to operate (the human proof)

The mentor is the practice's reference implementation; R19d's mirror language and the substrate ADR's "two front-ends, one substrate" both commit the agent practice to *the same examination* the human receives.

**The examination itself** (`REFLECTION_PROMPT`, `/api/mentor/private/reflect/route.ts:88-134`; same prompt structure on the public `/api/reflect:22-63`): Stage 1 proximity against the five levels; Stage 2 passions with root/sub-species/false-judgement; Stage 3 "what did they do well" (affirmation is part of the method); Stage 4 sage perspective ("what would right reason suggest differently") + an evening prompt. "Be warm but honest. The user is here to grow, not to be flattered." The mirror principle (R19d, `manifest.md:217`) is enforced *inside the prompt*: the framework examines one's own reasoning, never others'.

**The loop closes server-side, every call.** Each reflection: (1) writes a `reflections` row; (2) upserts each passion into the practitioner's passion map (normalised to the 4 roots); (3) records a hub-scoped `mentor_interactions` row (proximity, passions, validated `mentor_observation`, mechanisms applied); (4) recomputes a deterministic rolling-window pattern analysis (90 days / up to 100 interactions) stored in `mentor_profiles.pattern_analyses`; and (5) **injects the recurring-pattern summary into the *next* reflection's context** ("RECURRING PATTERNS DETECTED ACROSS PRIOR INTERACTIONS… diagnostic, not punitive") (`sage-mentor/profile-store.ts:1072-1170`; route `:299-479`). The human practice has retention, trajectory, and pattern-feedback *by construction*.

**What the score is supposed to change (human side):** not a number going up — the passion map evolves, the proximity trend and direction emerge from the window, milestones are qualitative ("first action with zero passions identified"), and the next examination is *contextualised by the record* (D16's `proximity_ring_data.recent_trajectory`; D17's delta vocabulary `improving/stable/declining` with confidence weighting that refuses to claim a trend from a single instance — `progression-delta.md:163-184,253-263`).

**Independence is designed in (R20b):** "Success means users who need the tool less over time" (`manifest.md:227`); the A18c dependence signal exists on the mentor path. Over-consultation is therefore not just inefficiency — the methodology itself names it as a failure pattern to be coached away.

**The mentor is also the methodology's source of new product content:** Sage Calling's six stages were "locked from the 2026-05-17 private mentor consultation" (`purpose-discovery-product-design.md:4`); the coverage_status credential-honesty design came from a Stoic-Brain consultation (`2026-05-26-sage-practice-exploration-close.md:18,22`). This is the established channel the founder's hard constraint points at: **methodology changes go through the mentor; mechanism changes go through build sessions.**

## 4. Expected operation — function by function (the baseline Part 2 measures against)

**4.1 Discovery + calling (when an agent should consult).** Sage Calling serves the *purposeless* agent (six stages, Q1–Q6, five-spec handoff into the substrate — `purpose-discovery-product-design.md:15,50-120`); an agent arriving with a task does not engage it. For in-task consultation, the designed integration points are the plugin loop hooks — "impression-capture, action-space-generation, post-action verification, subagent-handoff" (`ADR-stoic-agent-substrate-concept.md:119`) — and the wrapper cadence R5 prices: "guard + score + optional iterate" per consequential invocation (`manifest.md:125`), with risk-class mapping at the gate (standard→quick, elevated→standard, critical→deep — `/api/guardrail/route.ts:96-103`). **No adopted document prescribes consulting at every finding**; the P1 leg-B density came from the frozen test sheet's own §4(ii) ("each major finding before it is written") (`/drafts/2026-06-10-p1-comparison-test-design.md:30`). The intake side of consultation is AC-13's three tiers (force / soft / withhold).

**4.2 Scoring (what a score is supposed to change).** A score is an *examination result that redirects the work in flight*: the structured assessment (signed Layer2Assessment) feeds machine consumption — thresholds, gates, profiles — while the prose carries the correction to the reasoner (D16's two-shape commitment, `score-in-reply.md:138-143`). On the agent side the score is also *evidence*: the signed assessment is what R18f requires the accreditation write to carry (`manifest.md:208`).

**4.3 Redirection.** Every negative finding names the false judgement *and* the correct judgement (Rule 5; `improvement_path`); the gate converts proximity-vs-threshold into an action recommendation. Redirection is the practice's mid-task value, and the P1 evidence confirmed it operates (4 documented redirections; forensic §4).

**4.4 Loop closure (reiterate → re-examine).** Designed as `prior_feedback` / iterate (4.2.3 above; `canonical-framework.md:132`; `manifest.md:125`), deferral re-scoring (AC-15), and Reflect's FD-R2 cross-session check. Intended shape: after a redirection is adopted, the corrected reasoning is examined again — closing examine → redirect → **re-examine** — and retrospective updates flow into the longitudinal record (`progression-delta.md:313-321`).

**4.5 Reflect.** Session-close only (SR-3), four deterministic triggers (TR-01..04 — incl. TR-02: session closes with a completed SageReasoning pass), six questions reviewing the causal chain, profile update **through Sage Assent's engine** (SR-4: evidence submitted; the grade engine with hysteresis decides), purpose-fit routing (RS-1..4), and `opening_orientation` — "one practitioner leaving a note for another who will occupy the same reasoning space tomorrow" (`sage-reflect-product-design.md:262-273`). Reflect is **the product that converts sessions into development**; without it the practice is, by R19e's own words, not an ongoing practice.

**4.6 Accreditation (what the grade attests).** "Observable reasoning patterns as measured against the Stoic philosophical framework… not safety, ethics, or trustworthiness in any absolute sense" (R18a, `manifest.md:200`). The profile of record carries the 5-level senecan grade, typical_proximity, four progress dimensions (level ≠ direction), direction_of_travel, persisting passions, over a **rolling evaluation window with hysteresis — "no single session moves a grade"** (`sage-reflect-product-design.md:194-213`). The grade is explicitly a *direction* statement, not a verdict: "The question the profile answers is not 'how good is this agent' but 'in which direction is this agent moving, and what is the next step'" (the mandatory R19d framing note, `sage-reflect-product-design.md:255`). R18f: no credential without verifiable examination. The K1 coverage_status design extends the same honesty to gaps in coverage (`2026-05-26` closes).

**4.7 The audit narrative (what the auditor-facing record is supposed to contain).** Three artefacts are designed: (a) the **signed Layer2Assessment** — the authoritative, verifiable record (A3 signing; AC-10 provenance/use-policy tags); (b) the **L3 prose** — the readable verdict paired with its input, per the founder's accepted correction "the after-the-fact audit narrative pairing each L1 input with a readable verdict" (`forensic-execution-analysis.md:60`); (c) the **accreditation record** carrying the full provenance chain of signed assessments (R18f; leg B's write embedded all 12). Server-side, A12 audit events retain *structural* facts only (latencies, costs, trigger codes, booleans — `reason/route.ts:948-972`) — a posture consistent with R17's minimisation/intimate-data rules, which treat introspective content as the most protected class (`manifest.md:179-188`; SR-12 applies R17b/c/h/i to agent reflection content). **The designed tension to respect:** the auditor story wants narratives retrievable; R17 wants intimate content minimised, retention-limited, and deletable. Any retention mechanism must satisfy both.

**4.8 Trajectory over time (the profile).** The methodology requires it (2.3 above); the *designed* carriers on the agent side are: Sage Assent's `agent_accreditation` profile + window aggregator (Live, but fed in-memory; the `evaluated_actions` table "is not migrated… the live Sage Assent runs the window in-memory" — `sage-reflect-product-design.md:357`), Sage Reflect's Q5 profile updates (Live), the eight carried-context Layer1Schema fields incl. `history_window`/`carried_profile` (**accepted but inert** — `layer2-mechanisms.ts:2069-2078`), and D17's prior-state read (adopted for the practitioner side; never built for `/api/reason` agent calls). `/api/reason` per-call scoring is per-instance *by design* — but the design surrounds it with a profile layer the agent path does not yet have.

## 5. What the P1 evidence is measured against (summary for Part 2)

The intended operating model, in one paragraph, fully cited above: an agent **opens with purpose** (given, or found via Calling), **examines impressions at consequential decision points** (reason/guard cadence per R5, with AC-13 clarification and AC-14 withholding available), **receives scores that redirect the work**, **re-examines corrected reasoning** (iterate / prior_feedback / deferral resolution), **closes the session with Reflect** (profile update through the Assent engine; opening note for the next session), and **carries a longitudinal profile** (grade + proximity + dimensions + direction, hysteresis-protected) that the **accreditation honestly attests** (R18a/f; coverage_status; R19e), with **signed assessments + readable narratives** available to the auditor and **structural-only retention** server-side under R17.
