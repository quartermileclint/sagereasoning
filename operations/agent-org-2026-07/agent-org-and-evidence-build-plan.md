## 1. The program in one paragraph

The founder's three org questions (roster gaps → per-agent permissions/budgets → a founder console) and the evidence gaps blocking the project's own gates (the stale 0h value verdict; the S11 readiness standard's unmet parts 1–3; the un-measured Layer-1 extraction question) are ONE program, joined at a single insight: **staffing the startup with sage-practice-harnessed agents can generate the multi-identity, multi-domain evidence base the S11 readiness standard's parts (1)–(2) currently lack** — real work, not synthetic test load, ON THE SUBSET of agents whose operating surface actually carries the Gate-1 harness (see §1a — this is now a disclosed conditional, not an unqualified equivalence).

**§1a — two disclosed bounds on the central claim (v2 fold, PROACT-6 + SEQ-7):**
1. **Surface-conditional.** The evidence dividend applies ONLY to agents whose election E1 resolves to the Claude-Code-loop-with-Gate-1-harness surface. An agent operating on the website runtime or in Cowork serves the org function but generates zero harness records — it does not feed Track B. P4 and P8 must not silently assume every agent contributes evidence.
2. **A qualitative bound the mentor's "representative distribution" standard will independently probe (not pre-judged here):** the observed distribution this program generates comes entirely from INTERNAL staff working on — and in some roles editing — the very project that builds and hosts the instrument measuring them. This is disclosed as a standing methodological question for the eventual mentor re-examination, not resolved by this plan. "More identities" answers a quantity question; it does not by itself answer whether internal, self-referential work is "representative" in the standard's sense.

The org build and the evidence build remain one build where they genuinely overlap (harnessed agents), and two separate builds where they don't (non-harnessed agents still get calling + provisioning + governance under this program, without an evidence claim attached).

## 2. Standing constraints (bind every session below)

- **Nothing is pre-approved.** Each session opens under 0d-ii at its named tier; Critical sessions run the full 0c-ii Critical Change Protocol; the founder performs every live mint/revoke/SQL/Vercel/install op (PR17); the AI guides and verifies.
- **MEASURE throughout.** No session in this plan binds any examination result to any agent's ability to act. The intervention engine stays advisory; the calling gate stays measure-mode; ENFORCE remains S11, readiness-gated, refused.
- **Weights BLOCKED.** Nothing here produces, offers, or supports a training-signal use.
- **Test/benchmark AND verification/smoke traffic** is tagged, `retain_until`-governed, and excluded from billing/trajectory/readiness samples — every session that generates it names it at close **and the session that generates it is the one that tags it** (v2 fold, PROACT-5 — no traffic class ships untagged; the prior draft named the exclusion rule but not who executes it or that per-agent verification-smoke traffic on a STANDING credential is the same class as one-off benchmark traffic).
- **No standing automation without a named gate.** Any mechanism that runs unattended on a schedule or a hook — including any status/console generation — is itself a Critical-tier decision (deployment-configuration-adjacent) and must be named as such if elected; the default in this plan is manual, AI-run-at-session-close artifacts, never a cron/hook (v2 fold, PROACT-7).
- **Going unattended is its own gated event.** Provisioning a credential and installing a harness (P4) is NOT the same event as authorizing an agent to act without the founder present. The default posture for every newly-provisioned agent is **attended-only** until a separate, explicit "activate unattended operation" step runs — itself Critical-tier, requiring a founder-signed permissions-matrix row (P5) to exist FIRST (v2 fold, PROACT-2 — the single most important addition in this revision).
- **A hard floor on the proactive envelope.** No permissions-matrix row, however signed, may grant an agent Supabase-service-role access, Vercel deploy/env access, production credential mint/revoke capability, or any other op class §2's first bullet reserves to the founder. These remain founder-only regardless of matrix content — a structural floor, not a per-matrix policy choice (v2 fold, PROACT-3).
- **R18:** no public-surface claim changes without founder sign-off in the session that makes them. The AE-2 R18 docs remain a separate, already-queued item outside this plan.
- **Credential discipline:** least-privilege UPC capabilities per credential; per-credential daily/monthly limits set deliberately (never the 30/1/1 defaults for a working agent — the documented starve class); every org-program credential lands in **the ONE ledger this plan owns** — see §5 (the "decide later" framing is removed; v2 fold, PROACT-4).
