**Founder direction this session:**
1. **Blocker convention:** Option A — `blocker` carries remaining-work text only; achievement description belongs in `notes` or `desc`.
2. **Inventory rendering:** When `blocker` is non-empty, only the blocker cell renders red — not the whole row.
3. **Map rendering:** When `blocker` is non-empty, a small red marker appears on the node (top-left corner). Label text reverts to neutral.
4. **Conditional review rows:** The 5 rows whose blocker is "Verified at X; revisit if Y" get cleared. Their text moves to `notes` with a `⚠ ` prefix; the renderer detects this prefix and renders the notes cell red. (No schema change — text-prefix convention.)

## Section 3 — SKILL.md Pass 4 enhancement

Append to the existing Pass 4 contradiction checks in `/.claude/skills/sage-registry-update/SKILL.md`:

### Enhancement 3a — Broaden integration-claim verb set

In the Pass 4 §"Status × notes checks" section, broaden the achievement-claim verbs that flag stale `notes`. Current implicit set (per 2026-04-28 v1.2.2 experience): `Verified` / `verified end-to-end` / `consume canonical`. Add:

- `integrated`, `Verified at`, `Verified across`, `Verified end-to-end` (case-insensitive)
- `now consumes`, `wired through`, `connects via`
- `consumes canonical` (case-insensitive)
- `Confirmed`, `Validated`, `Complete` (case-insensitive)

If a row's `blocker` contains any of these AND `notes` contains "Not integrated" / "Isolated" / "stub only" / "Not yet" / "Pending" — flag as `blocker_corrected_notes_stale`.

### Enhancement 3b — Achievement-language-on-Verified-rows check (new)

Add a new check under Pass 4: if a `status: verified` row's `blocker` contains achievement language but no next-step language, flag for blocker pare-down.

**Achievement language:** `Verified` / `Confirmed` / `Complete` / `Validated` (case-insensitive).
**Next-step language:** `Next:` / `Outstanding:` / `Remaining:` / `Pending:` / `P[0-9]:` / `TODO:` (case-insensitive).

Heuristic outcome:
- Achievement only, no next-step → "Pare blocker; achievement description belongs in `notes` per Q2 convention."
- Both → "Pare blocker to next-step text only; preserve achievement description in `notes` if not already present."
- Next-step only → consistent, no action.

### Enhancement 3c — ⚠ prefix convention (new)

Document the `⚠ ` notes prefix convention adopted 2026-04-29:

> When a row's `blocker` is cleared (no actively scheduled work) but the row has a conditional review trigger ("revisit if X", "Verified at current scope; ongoing review under Y"), the conditional-review text moves to `notes` with a `⚠ ` (warning sign + space) prefix. The HTML renderer detects the prefix and renders the notes cell red. This signals "no scheduled work; future review noted" without using the `blocker` field for non-actionable items.
>
> The marker is U+26A0 WARNING SIGN. Apply at the start of the notes text. The renderer matches `notes.trim().startsWith('⚠')`.
